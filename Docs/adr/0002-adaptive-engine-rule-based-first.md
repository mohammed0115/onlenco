# ADR 0002: Adaptive engine is rule-based first; ML is opt-in later

Date: 2026-05-07
Status: Accepted

## Context

Adaptive learning typically uses Item Response Theory (IRT) and machine-
learned weakness predictors. We have very little student data, no labelled
training set, and a bilingual user base whose mistakes do not look like
existing English-learner corpora.

## Decision

- Theta updates use a 1PL Rasch logistic with `alpha=0.1`, clamped to
  `[-3, +3]`. Difficulty is rescaled from `[0,1]` to `[-3,+3]` for unit
  parity.
- Weakness priority is a transparent linear combination of frequency
  (absolute, capped), severity (1–10), and recency (exponential decay
  half-life of 14 days) with weights `0.5/0.4/0.1`.
- Recommendations are generated by deterministic rules; ML stays out
  until we have at least a few thousand attempts per skill.

## Consequences

- Every score in the system is explainable to instructors and students.
- No training pipeline, no model registry, no drift monitoring needed.
- When data accumulates, the same `weakness_engine.py` and
  `recommendation_engine.py` interfaces can wrap a Naive-Bayes (or richer)
  predictor without changing callers.
- Trade-off: priority weights are educated guesses. They will need to be
  revisited based on real student outcome data.
