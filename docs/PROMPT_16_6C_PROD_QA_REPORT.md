# تقرير QA إنتاجي — Prompt 16.6C (لوحات الإدارة والمعلم + auth)

**التاريخ:** 2026-06-04
**المنهج:** متصفح حقيقي (Selenium + Chrome headless) على `https://onlenco.academy` بتسجيل دخول فعلي، 9 لقطات (صفحة × مقاس) + قياس overflow برمجياً، ثم مراجعة بصرية متوازية (workflow: 5 مراجعين + تجميع).

اللقطات: [`docs/screenshots/p166c-prod-qa/`](screenshots/p166c-prod-qa/) · بيانات الـ overflow: `overflow_report.json`.

---

## 1. الملخص التنفيذي

- **صفر تمرير أفقي** على كل الصفحات التسع (`documentElement/body scrollWidth == clientWidth`) على الديسكتوب (1366) والموبايل (390). معيار الـ shell/overflow في 16.6C **محقّق على الإنتاج**.
- **sidebar واحد** غير مقصوص يميناً (RTL)، أيقونات منسّقة، العنصر النشط مميَّز؛ على الموبايل drawer مغلق + hamburger والمحتوى بعرض كامل.
- **لا نصوص داخلية/JSON مسرّبة** في أي صفحة.
- **عيب وحيد حقيقي في الكود أُصلح:** تسجيل الدخول كان يتجاهل `?next=` → الآن يحترمه بأمان.
- باقي الملاحظات البصرية سببها **CSS قديم على الإنتاج** (الإصلاحات موجودة محلياً، تنتظر النشر).

**القرار:** لا P0/P1. التصميم مستقر على الإنتاج فيما يخص الـ shell/الجداول/RTL/الموبايل. يتبقّى نشر العمل المتراكم لإغلاق ملاحظات الـ CSS القديم.

---

## 2. فحص الـ URL المطلوب: `/auth/?next=/placement/`

| السلوك | النتيجة |
|---|---|
| زائر مجهول → `/placement/` | ✅ يُحوَّل صحيحاً إلى `/auth/?next=/placement/` (يحفظ الوجهة) |
| بعد الدخول (كان) | 🔴 يتجاهل `?next=` → الأدمن يهبط على `/admin/` |
| بعد الدخول (الآن) | ✅ **أُصلح** — يحترم `?next=` الآمن (نفس الأصل) بعد بوابة الـ onboarding |

**الإصلاح** ([accounts/views.py](accounts/views.py#L150)): أضفت `_safe_next(request)` (يتحقق من `url_has_allowed_host_and_scheme` لمنع open-redirect) و`_post_login_destination` صار يحترم `?next=` بترتيب: **بوابة الـ onboarding/placement تفوز دائماً** (لا يمكن تخطّيها برابط) ← ثم `?next=` الآمن ← ثم الوجهة الافتراضية حسب الدور. 3 اختبارات جديدة (يحترم الآمن / يتجاهل الخارجي / fallback).

## 3. نتائج المراجعة البصرية (P0–P3)

**P0 (حاجبة):** لا يوجد. · **P1 (حرجة):** لا يوجد.

**P2 (مهمة):**
- ✅ **تجاهل `next` عند الدخول** — أُصلح في الكود (القسم 2).
- 🟡 **جدول طلاب المعلم على الموبايل** يفقد بنية الأعمدة (يظهر «الاسم» فقط والقيم تتراصّ). **السبب: CSS قديم على الإنتاج** — الكود المحلي بالفعل يلفّ الجدول في `.table-wrap` مع `.teacher-table { min-width: 760px }` و`overflow-x: auto`، أي يمرّر أفقياً ويحفظ الأعمدة. يُغلَق بالنشر.

**P3 (تجميلية):**
- صف أزرار الترويسة على الموبايل (admin) يُقصّ الزر الأيسر؛ و«تسجيل الخروج» يزدحم مع البحث؛ و«إنشاء كورس» يلتفّ سطرين. كلها بدون تجاوز للصفحة. الـ CSS المحلي يحتوي `flex-wrap: wrap` على صفوف الإجراءات — تُغلَق بالنشر.

## 4. الجدول: نتائج الـ overflow (الديسكتوب 1366 / الموبايل 390)

| الصفحة | doc | body | sidebars |
|---|---|---|---|
| auth (next=/placement/) | 0 | 0 | 0 (صحيح للصفحة العامة) |
| /admin/ · /admin/students/ | 0 | 0 | 1 |
| /teacher/dashboard/ · /teacher/students/ | 0 | 0 | 1 |
| كل ما سبق × موبايل 390 | 0 | 0 | 1 (drawer مغلق) |

> الـ «offenders» على الموبايل = الـ drawer المغلق خارج الشاشة عمداً (مقصوص بـ `overflow-x: clip`) — سلوك صحيح، لا يسبّب تمرير صفحة.

---

## 5. حالة النشر (مهم)

الإنتاج يعمل عند مستوى **البرومبت 2** (ظهور «الحصص المباشرة»)، لكن يبدو أنه يخدم **CSS قديم** (مشكلة الـ static/cache في القسم 16). العمل المحلي **متقدّم**: 16.6C كامل + باني الكويز + Marketplace 1/2/3 + الشهادات + إصلاحات الأخطاء + إصلاح `?next=`.

**التوصية:** نشر العمل المتراكم عبر `update.sh` (مع `collectstatic` ورفع نسخة الأصول) يُغلق كل ملاحظات الـ P2/P3 البصرية، ثم إعادة تشغيل نفس فحص الـ QA للتأكيد.

---

## 6. القرار النهائي

**«يحتاج إصلاحات بسيطة → أصبح جاهزاً بعد النشر».** لا مشاكل P0/P1. عيب الـ `?next=` (الوحيد في الكود) أُصلح ومُختبَر. باقي الملاحظات تُغلَق بنشر العمل المتراكم الذي يحوي إصلاحات 16.6C البصرية بالفعل.
