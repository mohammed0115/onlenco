## 1. الملخص التنفيذي

التصميم على الإنتاج **سليم وخالٍ من أي تجاوز أفقي أو أعطال هيكلية**. لا توجد مشاكل P0/P1. النتيجة النهائية للـ workflow: **«يحتاج إصلاحات بسيطة»** — مشكلتان P2 وثلاث ملاحظات P3.

نقطة مهمة: **أغلب ملاحظات P2/P3 البصرية سببها أن الإنتاج يشغّل أصولاً (CSS) أقدم من الكود الحالي** — الإصلاحات (`table-wrap` + `min-width` للجداول، التفاف أزرار الترويسة) موجودة بالفعل في الكود المحلي لكنها **لم تُنشر بعد** (الإنتاج عند مستوى البرومبت 2). الاستثناء الوحيد هو عيب الكود الحقيقي في تجاهل `?next=`.

## 2. القياس الموضوعي للـ Overflow (الإثبات البرمجي)

على كل اللقطات التسع (صفحة × مقاس):
```
document.documentElement.scrollWidth - clientWidth = 0
document.body.scrollWidth - clientWidth         = 0
```
**لا يوجد شريط تمرير أفقي على مستوى المتصفح في أي صفحة** — لا admin ولا teacher، لا desktop ولا mobile. عدد الـ sidebar = 1 في كل مكان (لا تكرار). العناصر «المتجاوزة» الوحيدة هي الـ drawer المغلق خارج الشاشة على الموبايل (سلوك صحيح، مقصوص بـ overflow-x: clip) ومحتوى داخل `.table-wrap` (مسموح به صراحةً).

## 3. معايير 16.6C المتحقّقة على الإنتاج ✅

- صفر تجاوز أفقي (admin + teacher، desktop + mobile).
- شريط جانبي واحد، يميناً (RTL)، أيقونات محاذاة سليمة، العنصر النشط مميَّز، **لا نص خام**.
- انهيار الشريط الجانبي إلى drawer (hamburger) مغلق على الموبايل، والمحتوى بعرض كامل، لا شيء تحته.
- لا JSON ولا سلاسل تقنية ولا نص داخلي مُسرَّب في أي صفحة.
- محاذاة RTL صحيحة، والمحتوى المختلط (عربي/إنجليزي/بريد/أكواد) يُقرأ بنظافة.
- الجداول داخل بطاقات، زر «فتح» غير مقصوص (على الديسكتوب).
- صفحة الدخول العامة نظيفة بلا شريط جانبي، زر أساسي واحد، مبدّل لغة.

## 4. تدفّق الدخول — الـ URL المطلوب فحصه `‎/auth/?next=/placement/‎`

- الزائر المجهول على `/placement/` → **يُحوَّل صحيحاً** إلى `/auth/?next=/placement/` (بوابة التسجيل تحفظ الوجهة). ✅
- **لكن بعد تسجيل الدخول كان يُتجاهَل `?next=` تماماً** — `_post_login_destination` كان يعتمد فقط على حالة الـ onboarding ثم الوجهة الافتراضية حسب الدور، فهبط الأدمن على `/admin/` بدل `/placement/`. **عيب كود حقيقي يكسر الروابط العميقة (deep-linking).**

**الإصلاح المُطبَّق (هذا الـ commit):** `_post_login_destination(user, request)` صار يحترم `?next=` **الآمن من نفس الأصل** — بعد بوابة الـ onboarding (التي تظل لها الأولوية لمنع تخطّي تحديد المستوى)، وقبل الوجهة الافتراضية. روابط خارجية/غير آمنة تُتجاهَل (حماية من open-redirect عبر `url_has_allowed_host_and_scheme`). + اختبارات.

## 5. قائمة المشاكل (P0–P3)

**P0 / P1:** لا يوجد.

**P2 (مهمة):**
1. **تجاهل `?next=` عند الدخول** — *أُصلح في الكود الآن* (القسم 4).
2. **انهيار بنية جدول طلاب المعلم على الموبايل (390px)**: تظهر ترويسة «الاسم» فقط وتتراصّ القيم بلا تسميات. **مُصلَح محلياً بالفعل** — القالب يلفّ الجدول في `.table-wrap` و`.teacher-table { min-width: 760px }` (تمرير أفقي داخل البطاقة يحفظ الأعمدة). الإنتاج يشغّل CSS أقدم → **يُحَل بالنشر + collectstatic + hard-refresh**.

**P3 (تجميلية):**
- `/admin/` (390px): صف أزرار الترويسة أعرض قليلاً فيُقصّ الزر الأيسر. (CSS الترويسة المحلي يحوي `flex-wrap` — يُحَل بالنشر.)
- `/admin/students/` (390px): زر «تسجيل الخروج» متداخل مع حقل البحث (شظايا). (نفس السبب — أصول قديمة.)
- `/teacher/dashboard/` (390px): زر «إنشاء كورس» يلتفّ على سطرين (بسبب `flex:1`؛ مقروء بالكامل، تجميلي بحت).

## 6. حالة النشر (سبب جذري لأغلب ملاحظات P2/P3)

الإنتاج عند **مستوى البرومبت 2** (الـ nav يُظهر «الحصص المباشرة» لكن ليس «المجموعات» من البرومبت 3). الأصول (CSS) المعروضة أقدم من الكود الحالي، فالقسم 16 من 16.6C (Static/Cache) ينطبق هنا. الإصلاحات البصرية موجودة في الكود؛ المطلوب **نشرها**:

```bash
cd /opt/onlenco && sudo bash scripts/update.sh   # يشمل migrate + collectstatic
# ثم Ctrl+Shift+R للتأكد من سقوط الكاش القديم
```
